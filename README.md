# GNG — Next.js

Next.js საიტი და ქართულენოვანი ადმინ პანელი. Next.js App Router, TypeScript, Tailwind CSS, **Neon PostgreSQL**, **Better Auth**, **Cloudflare R2**.

ფრონტი ეფუძნება მომხმარებლის გაზიარებული [Optik-ის ნიმუშის](https://optik-studio-recreated.akopov43.chatgpt.site) განლაგებას, ფოტოებსა და სექციებს. მომხმარებლის მოთხოვნით დამატებულია GNG-ის ლოგო და ქართული ტექსტები; დროებით გამოიყენება უკვე დაყენებული Noto Sans Georgian. ლოგოს ხილული სიგანეა 180 პიქსელი კომპიუტერზე და 144 — მობილურზე. კომპანიის ტექსტები და სერვისები მოწოდებული მასალებიდანაა; დარჩენილი შაბლონის პროექტები, გუნდი, ჯილდოები და შეფასებები მონიშნულია ნიმუშებად.

## გაშვება

Node.js 22.12 ან ახალი ვერსია. ტერმინალში:

```sh
npm install
npm run dev
```

მისამართი: http://127.0.0.1:3000. ბაზის პარამეტრების გარეშე ჩანს Optik-ის ოთხი მაგალითი; ისინი არ ემატება რეალური პროექტების ცხრილს. Neon-ის კონფიგურაციის შემდეგ გალერეა აჩვენებს მხოლოდ გამოქვეყნებულ ჩანაწერებს, ხოლო მთავარზე — რჩეულებს. ადმინი ბაზის გარეშე აჩვენებს გამართვის გვერდს. საკონტაქტო ფორმა ამ რეჟიმში შეტყობინებას ვერ ინახავს და წარმატებას არ აჩვენებს.

ორიგინალი აქტივები ინახება `public/optik/assets`-ში. Webflow-ის JavaScript არ იტვირთება; მენიუ და სლაიდერები React-ით მუშაობს. წყაროს CSS იზოლირებულია `.optik-site`-ში, რათა ადმინის სტილებზე არ იმოქმედოს. მისი რეგენერაცია: `node scripts/scope-optik-css.mjs`. ქართული ტექსტის ზომებისა და ლოგოს წესები ცალკეა `src/app/georgian.css`-ში. `npm run test:e2e` ამოწმებს ქართულ ნავიგაციას, ფორმებს, სლაიდერებს, ლოგოს ზომას, ტექსტის ჩატევასა და მობილურ განლაგებას.

## Neon და ავტორიზაცია

1. შექმენით Neon პროექტი და ცალკე development branch. `.env.example` დააკოპირეთ `.env.local`-ად.
2. `DATABASE_URL`-ში ჩაწერეთ Neon-ის PostgreSQL connection string, რეკომენდებულია pooled endpoint და `sslmode=require`.
3. `BETTER_AUTH_SECRET` შეავსეთ შემთხვევითი, მინიმუმ 32 სიმბოლოს საიდუმლოთი. გენერაცია: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.
4. `BETTER_AUTH_URL` და `NEXT_PUBLIC_SITE_URL` მიუთითეთ საიტის ნამდვილ origin-ზე. ლოკალურად გამოიყენეთ `http://localhost:3000`.
5. გაუშვით ქვემოთ მოცემული ბრძანებები:

```sh
npm run db:migrate
npm run db:seed
npm run admin:create
```

მიგრაცია ჯერ Better Auth-ის სქემას ქმნის, შემდეგ `db/migrations`-ის ვერსირებულ ფაილებს. Seed ხელახლა გაშვებისას არსებულ ჩანაწერებს არ ცვლის. თავდაპირველი 25 პროექტი მონახაზია: ფოტოები, აღწერები და წლები მოწოდებული არ იყო.

ადმინისტრატორის შექმნისას ტერმინალი ითხოვს ელფოსტასა და დაფარულ პაროლს. პაროლი მინიმუმ 8 სიმბოლო. საჯარო რეგისტრაცია გათიშულია; უფლებები ყოველ დაცულ კითხვასა და ცვლილებაზე მოწმდება. შესვლა: `/admin/login`. პაროლის აღდგენა: `npm run admin:create -- --reset-password` — არსებული ადმინისტრატორის ელფოსტით; ძველი სესიები გაუქმდება.

## Cloudflare R2

შექმენით საიტის სურათებისთვის განკუთვნილი R2 bucket და ამ bucket-ზე შეზღუდული Object Read & Write S3 credentials. `.env.local`-ში შეავსეთ:

```dotenv
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET_NAME=
R2_PUBLIC_URL=https://media.example.com
```

`R2_PUBLIC_URL` უნდა მიუთითებდეს bucket-ის დაკავშირებულ საჯარო custom domain-ზე (development-ზე შეიძლება r2.dev URL). ატვირთვა ხდება სერვერიდან, ამიტომ browser CORS საჭირო არ არის. ატვირთვის ფორმა იღებს JPG/PNG/WebP/AVIF-ს 5 MB-მდე, ამოწმებს რეალურ სურათს, შლის მეტამონაცემებს და ინახავს ოპტიმიზებულ WebP-ს. არსებული სურათის URL-ის მითითებაც შეიძლება. გალერეიდან ამოღება შლის ბმულს პროექტიდან; R2 ობიექტი რჩება, რადგან სხვა კონტენტი შეიძლება იყენებდეს.

## ფუნქციები

- მთავარი, ჩვენ შესახებ, პროექტების სია/დეტალი, კონტაქტი.
- ადმინი: hero, პროექტები/გალერეა/გამოქვეყნება/რიგითობა, კონტაქტები და მიღებული შეტყობინებები.
- მონახაზები საჯარო მოთხოვნებში არ ბრუნდება. გამოქვეყნებისთვის საჭიროა აღწერა და მთავარი ფოტო.
- საკონტაქტო ფორმა შეტყობინებებს ინახავს Neon-ში; ელფოსტის გაგზავნა ამ ვერსიაში არ შედის.
- ფორმის მუდმივი საათობრივი ლიმიტები: 5 გაგზავნა ერთ იდენტობაზე, 100 ჯამურად. `TRUSTED_IP_HEADER` დააყენეთ მხოლოდ მაშინ, როცა ჰოსტინგის proxy გარანტირებულად გადაწერს ამ header-ს; სხვაგვარად ლიმიტი ელფოსტით ითვლება.
- ადმინის ხედვის სიაში ჩანს ბოლო 500 შეტყობინება; ძველი ჩანაწერები ბაზაში რჩება.

## შემოწმება და ჰოსტინგი

```sh
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run test:admin
npm start
```

Playwright იყენებს ლოკალურ Chromium-ს; საჭიროების შემთხვევაში `npx playwright install chromium`. უკვე არსებული ბრაუზერისთვის შეიძლება `PLAYWRIGHT_CHROMIUM_EXECUTABLE`-ის მითითება. Unit/database tests ამოწმებს ვალიდაციასა და SQL სქემას იზოლირებულ PGlite PostgreSQL-ში. საჯარო E2E განკუთვნილია ბაზის გარეშე გაშვებული სერვერისთვის და ამოწმებს გვერდებს, მობილურ მენიუს, ცარიელ მდგომარეობებსა და დაუკავშირებელი ადმინის დაცვას.

`npm run test:admin` მოითხოვს წინასწარ წარმატებულ build-ს. ის დროებით უშვებს იზოლირებულ PostgreSQL-ს `127.0.0.1:54329`-ზე და production საიტს `127.0.0.1:3001`-ზე, ასრულებს მიგრაციებს, ამატებს შემთხვევითი პაროლის მქონე სატესტო ადმინისტრატორს და ბრაუზერში ამოწმებს კონტენტის მართვის სრულ სცენარს. დასრულებისას ბაზა და ორივე სერვერი იხურება; რეალურ Neon/R2-ს არ უკავშირდება. რეალური ღრუბლოვანი კავშირები ცალკე უნდა შემოწმდეს პარამეტრების დამატების შემდეგ.

გამოსაქვეყნებლად საჭიროა Next.js Node.js runtime-ის მქონე ჰოსტინგი; სტატიკური export ამ ადმინ პანელს ვერ აამუშავებს. Neon არის ბაზა, R2 — ფაილების საცავი. Production-ზე დააყენეთ იგივე გარემოს ცვლადები რეალური HTTPS origin-ით და მიგრაციები გაუშვით მიზნობრივ ბაზაზე. გარემოს საიდუმლოებები არ უნდა მოხვდეს Git-ში ან `NEXT_PUBLIC_` ცვლადებში.

## შინაარსი და დიზაინი

ქართული ტექსტების წყაროა საქაღალდეში არსებული DOCX ფაილები; ლოგო მოწოდებულია მომხმარებლის მიერ. საწყისი დეკორატიული სურათები გადმოტანილია მომხმარებლის Optik reference საიტიდან. ისინი არ წარმოადგენს GNG-ის პროექტების დადასტურებულ ფოტოებს. რეალური პროექტების ატვირთვა და საკონტაქტო მონაცემების შევსება ხდება ადმინში.

`src/lib/content.ts` — კომპანიის ტექსტები; `src/lib/seed.ts` — საწყისი მონაცემები; `src/app/georgian.css` და `src/components/site` — საჯარო დიზაინი; `src/components/admin` — მართვის ფორმები; `src/lib/actions` — უფლებები/შენახვა. შრიფტების შემდგომი ცვლილებისთვის `src/app/globals.css`-ში გამოიყენეთ `--font-sans` და `--font-heading`; ახალი შრიფტის ფაილები ჩატვირთეთ ძირითად layout-ში. ვიზუალური რედიზაინი შესაძლებელია მონაცემთა მოდელისა და ავტორიზაციის შეცვლის გარეშე.
